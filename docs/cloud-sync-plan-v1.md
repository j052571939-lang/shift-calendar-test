# 班表助理｜跨平台雲端同步規格草案 v1

狀態：設計階段，尚未啟用任何雲端連線。正式版 V8.1.8 不修改。

## 目標
- iPhone、Android、PWA 使用同一個登入帳號取回個人班表。
- 每位使用者資料彼此隔離；未登入不傳資料。
- 原有本機資料仍可離線使用。
- 保留現有 JSON 手動匯出／匯入功能，避免依賴單一雲端服務。
- 「分享本月班表」只分享可見的班別、日期、假日，不包含記事、帳號、提醒時間或雲端備份內容。

## 現有本機資料（不可直接改名或清空）
localStorage key: shift_assistant_app_preview_01
{
  "schedule": {...} | null,
  "overrides": {"YYYY-MM-DD": "leave" | "overtime" | {"type":"overtime","shift":"day"|"night"}},
  "notes": {"YYYY-MM-DD": "私人記事"}
}
現有 JSON 備份格式：format=shift-assistant-backup, schema=1，data 含上述三欄。
升級時必須能讀取舊 schema=1，不可破壞既有備份。

## 擬定雲端紀錄
{
  "schemaVersion": 1,
  "userId": "由登入服務核發，不接受使用者自行指定",
  "revision": 1,
  "updatedAt": "由伺服器產生的時間",
  "payload": {
    "schedule": null,
    "overrides": {},
    "notes": {}
  }
}
雲端帳號、認證權杖不得包含於 JSON 分享檔案。

## 同步安全規則
1. 首次登入：先讀取雲端資料，若本機及雲端都有資料，不自動覆蓋，提示選擇保留本機、使用雲端、或取消；操作前提供 JSON 備份。
2. 每次寫入：檢查 revision，遇到不同裝置同時修改時停止覆蓋並提示使用者處理。
3. 離線：寫入本機並標記待同步；重新連線後先比對版本。
4. 登出：不自行刪除使用者原本資料；清除本機資料須另外確認。
5. 雲端同步狀態：明確區分「本機已儲存」、「等待同步」、「雲端已同步」、「同步失敗」。
6. 資料庫權限：每個帳號只能讀寫自己的紀錄，需伺服器端規則驗證，不以畫面隱藏替代權限。
7. 不使用公開 GitHub Pages 儲存私人班表或記事；GitHub Pages 僅部署前端程式。
8. 上線前驗證免費額度、隱私規範、帳號刪除與資料匯出流程。

## 實作順序
A. 決定登入與雲端供應商（Firebase 或 Supabase，優先免費方案）。
B. 建立測試專案、登入、資料庫權限規則（需要使用者授權及操作）。
C. 在測試版新增「同步狀態」與明確的登入/登出控制。
D. 先測試全新帳號，再測試既有 B 班資料的安全遷移。
E. 測試 iPhone 換 iPhone、iPhone 換 Android，以及離線修改衝突。
F. 通過實機驗證後才評估正式版整合。

## 禁止事項
- 未登入或未同意不得自動上傳私人資料。
- 不得以同步失敗覆蓋本機資料。
- 不得把私人記事加入整月班表分享圖片。
- 不得修改正式版 V8.1.8。
