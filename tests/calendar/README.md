# V0.5.26 記事行事曆匯出與穩定性檢核

## 首發範圍
使用者決定只補記事行事曆通知相關功能，其餘新功能留上架後。此版提供事件時間、事件名稱／備註、提醒開關及提前時間，產生 .ics 檔案供行事曆匯入。它不是原生 EventKit 寫入，也不是 PWA 背景通知或已完成的 App Store 版本。

## 行為
- 所選日期記事卡片與日期視窗提供「匯出記事到行事曆」。
- 未儲存的日期視窗記事先正常儲存；失敗時保留草稿且不進入匯出。
- 可刪減事件備註；匯出不修改原記事、班表、Google 帳號資料或 Firestore schema。
- 時間取裝置時區並轉 UTC；支援跨午夜事件，提醒可關閉或提前 0／5／10／15／30／60／1440 分鐘。
- 資料留本機產生檔案，使用者自行選分享對象。匯出功能本身不新增網路請求。
- 分享取消或失敗都保留記事；無法分享時提供下載。
- 同次對話框相同內容沿用 UID；重新開啟會建立新 UID，重複匯入仍可能建立重複事件，畫面有說明。
- 行事曆匯入的事件不會隨班表助理記事修改而自動更新；此版沒有雙向同步。
- 編輯事件對話框開啟期間，雲端還原／合併暫停以避免重載丟失表單。
- 分享或下載後只提示需在行事曆確認，不宣稱「已加入」或「通知已啟用」。

## 檢核結果
- 29 項新增測試通過：iCalendar 獨立解析、跨日／時區、提醒開關與時間、錯誤日期、欄位限制、CRLF 組件注入、UTF-8 75 octet 折行、UID 驗證、DOM 操作、取消分享、分享失敗、未儲存記事／儲存失敗保護與雲端還原守門。
- 原 11 項三方合併／記事保護、9 項逾時模擬、22 項官方本機模擬器規則、4 項 Firebase SDK 11.10.0 本機模擬器整合均在 V0.5.26 重新通過。合計 75 項。
- 两個 script 區塊語法通過；未執行真實瀏覽器畫面 QA。
- 測試沒有存取正式 Firebase 或使用者資料，沒有發布安全規則。
- 以上是已涵蓋案例的檢查結果，不宣稱沒有任何漏洞。

## 真實驗收限制
**iPhone .ics 匯入及實際行事曆通知尚未驗收。** PWA 無法確認系統行事曆是否已儲存事件，也不能保證匯入後保留提醒；必須在行事曆核對。
Apple 說明 iPhone 可由 Mail 匯入 .ics；Safari／分享表單能否直接加入不能假設。畫面提供 Apple 郵件附件匯入說明。
來源：https://support.apple.com/en-ie/guide/iphone/ipha0d932e96/27/ios/27
格式：https://www.rfc-editor.org/rfc/rfc5545.html

原生 iOS 上架版本的直接加入行事曆（EventKit／EventKitUI）及本地通知仍未完成，不能把此 .ics 匯出稱為已完成原生整合。正式 V8.1.8 未修改。
