# V0.5.27：班表內整合記事事件

使用者修正需求：不要另行匯出／生成行事曆檔案。記事內直接設定日期、開始時間與提醒，分享與儲存分開，日期／時間等寬等高。其他功能上架後再加。

## 已實作
- 移除 V0.5.26 的 .ics 匯出視窗與按鈕。歷史快照保留便於回復。
- 原日期記事視窗內整合日期、開始時間、提醒開關、提前時間；日期沿用月曆所選日期（唯讀），改日期須在月曆選另一日。
- 一次儲存記事與提醒；改請假／加班或關閉視窗時也保護未儲存資料。儲存失敗原子回復。
- 月曆直接顯示記事時間；所選日期卡片顯示事件時間及記事提醒狀態，與上班提醒分開。
- 「分享已儲存記事」獨立按鈕；有草稿時先要求儲存，不由分享動作偷偷儲存。
- 日期與時間置於同一 grid，兩欄等寬、48px 等高。此為 CSS／DOM 檢查，尚未 iPhone 視覺實測。
- 前景頁面每 15 秒檢查記事提醒，到期顯示班表內提醒卡片；同一事件在同裝置避免重複顯示。逾時超過 90 秒不補發。

## 限制（不能宣称完整系統行事曆通知）
**此 PWA 僅能在班表頁面保持開啟且可見時顯示提醒；鎖屏、關閉 App、背景系統通知沒有完成。**
畫面有明確說明。沒有使用假的通知許可或宣稱已排系統提醒。完整背景通知仍需要原生 iOS 或實際 Web Push 排程服務與實測。
目前每個記事日期一組開始時間／提醒，不支援同日多事件、重複事件、事件移動、完整外部行事曆同步。

## 同步與相容
- schedule／overrides／notes 外層資料契約、Firestore schema=1 不變。
- notes 原文字仍為 yyyy-mm-dd -> string；時間設定以 @event:yyyy-mm-dd -> JSON string 附帶，旧版载入／儲存可保留未知 key。這是針對現有 string notes 的相容策略。
- 附帶資料包含事件 id、日期／時間、提醒設定、UTC 時間、裝置時區與記事內容版本指紋；不重複儲存完整記事文字。
- 指紋僅用來辨識舊客戶端變更而使時間設定失效，不是加密／安全雜湊。舊版改文或刪文時失配提醒不啟用。
- 新版改文會更新記事與附帶資料；清空事件時間及記事會一起刪除附帶資料。
- 三方合併將同一日期的記事文字與提醒附帶資料當作一組；兩個裝置分別改同一記事的文字與提醒時停止合併，不做錯誤配對。
- 備份還原接受有效附帶資料；舊客戶端改文造成失配時仍可還原記事，只忽略不相符時間設定。舊版備份還原驗證器不认识新附帶 key，因此測試／還原都應更新到 V0.5.27。
- 新增提醒附帶資料時檢查 800000-byte 同步容量上限；超過時保留原資料。
